# ⭐ 골드스타몰 (GoldstarMall)

Spring Boot + JPA + MySQL로 만든 온라인 쇼핑몰입니다.
프레임워크실습 기말 Term Project입니다.

손님은 상품을 둘러보고, 장바구니에 담거나 바로 주문하고, 배송 상태를 추적할 수 있습니다. 취소와 반품도 할 수 있습니다.
관리자는 주문, 회원, 상품, 상품평과 문의를 한 곳에서 관리합니다.

## 실행 방법

### 1. 준비물
- JDK 17
- MySQL 8.0 (`localhost:3306`)

### 2. DB 비밀번호 설정
MySQL root 비밀번호가 `1234`가 아니면 `src/main/resources/application.properties`의 password 줄만 고치세요.

```properties
# src/main/resources/application.properties
spring.datasource.password = 1234
```

- 접속 주소는 `localhost:3306`, 계정은 `root`입니다.
- `goldstarmall` 데이터베이스는 없으면 자동으로 만들어집니다 (`createDatabaseIfNotExist=true`).

### 3. 서버 실행 (테이블 자동 생성)
```bash
./gradlew bootRun        # Windows : gradlew.bat bootRun
```
- `spring.jpa.hibernate.ddl-auto=update`라서 엔티티를 보고 테이블이 자동으로 만들어집니다.
- 처음 실행할 때 관리자 계정(`admin` / `admin1234`)이 자동으로 생성됩니다 (`DataInitializer`).

### 4. 상품 / 시연 데이터 넣기
서버를 한 번 실행해 테이블이 생긴 뒤, MySQL 쿼리 콘솔에서 아래 파일을 **순서대로 한 번씩** 실행합니다.

| 순서 | 파일 | 내용 |
|---|---|---|
| 1 | `src/main/resources/sql/products.sql` | 상품 155개 (15개 카테고리), 상품 옵션 (노트북 백팩, 기능성 티셔츠) |
| 2 | `src/main/resources/sql/demo-data.sql` | 시연용 회원 7명, 주문 17건 (배송 상태가 골고루 섞여 있음) |

`demo-data.sql`을 넣은 뒤 서버를 다시 켜면 두 가지가 처리됩니다.
- 주문번호가 비어 있는 주문에 주문번호가 자동으로 채워집니다.
- 회원 등급이 누적 구매액에 맞게 다시 계산됩니다.

### 5. 접속
http://localhost:8080

## 주요 기능

### 손님
- **홈 화면**
  - 오늘의 할인 배너와 주간 할인표가 있습니다.
  - 카테고리 바로가기가 있습니다.
  - 상품 섹션: 오늘의 할인, 인기 상품, 로켓 배송, 신상품, 품절 임박
- **상품 목록** (`/products`)
  - 카테고리별 보기, 이름 검색, 페이지 나누기 (한 페이지 12개)
- **상품 상세**
  - 상품 정보, 판매자 정보, 배송/교환/반품 안내
  - 옵션 선택: 크기, 색상, 사이즈 등
  - 상품평: 별점, 배송완료된 구매자만 작성 가능
  - 상품문의
- **장바구니 / 바로 주문**
  - 수량 변경, 옵션별로 따로 담기
  - 받는 사람, 배송지 입력 (기본 / 추가 배송지 선택)
- **주문내역**
  - 배송 상태 추적: 주문접수 → 입고 → 출고 → 배송중 → 배송완료
  - 주문 취소: 배송완료 전까지, 결제 금액 전액 환불
  - 반품 신청: 배송완료 후 14일 이내, 하자 없는 상품만. 관리자 검수 후 환불
  - 끝난 주문은 주문내역에서 삭제 (숨김)
- **회원**
  - 회원가입, 로그인, 아이디 찾기, 비밀번호 재설정
  - 마이페이지에서 정보 수정, 비밀번호 변경, 추가 배송지 등록, 탈퇴
- **회원 등급**
  - 누적 구매액에 따라 일반 → 실버 → 골드 → VIP
  - 등급별 주문 할인
- **알림 🔔**
  - 내 문의에 답변이 달리거나 내 상품평에 코멘트가 달리면 알림이 옵니다.
  - 확인한 알림은 삭제할 수 있습니다.

### 관리자
- **주문관리**
  - 주문 검색: 주문번호, 주문자, 주문일시, 배송지
  - 배송 상태를 다음 단계로 변경
  - 주문번호 수정
  - 주문 거절: 출고 전까지, 사유 입력, 전액 환불
  - 반품 승인 / 거절
  - 끝난 주문 삭제
- **회원관리**
  - 회원 검색, 정보 수정, 삭제
  - 회원별 누적 구매액 확인
- **상품관리**
  - 상품 등록, 가격 / 재고 수정, 삭제
  - 로켓 배송 켜기 / 끄기
  - 누적 판매량 / 매출 확인과 초기화
- **리뷰/문의**
  - 상품문의 답변, 상품평 코멘트
- **처리 대기 알림**
  - 상단 메뉴에 반품 신청, 답변 대기 문의, 코멘트 대기 상품평 개수가 빨간 숫자로 표시됩니다.

## 쇼핑몰 규칙

### 배송 상태 (`ShippingStatus`)

| 상태 | 손님 | 관리자 |
|---|---|---|
| 주문접수 → 입고 → 출고 → 배송중 | 주문 취소 가능 | 다음 단계로 변경, 출고 전(주문접수, 입고)이면 거절 가능 |
| 배송완료 | 14일 이내 반품 신청, 주문내역 삭제 | 주문 삭제 |
| 반품신청 | - | 반품 승인(환불) / 거절(사유 입력) |
| 주문취소 / 주문거절 / 반품완료 | 주문내역 삭제 | 주문 삭제 |

취소, 거절, 반품완료 처리를 하면 세 가지가 함께 처리됩니다.
- 결제 금액 전액이 환불 기록으로 남습니다.
- 재고가 돌아옵니다. 옵션 상품이면 옵션 재고도 함께 돌아옵니다.
- 판매량과 매출에서 빠집니다.

### 회원 등급 (`MemberGrade`)
누적 구매액은 배송완료된 주문의 결제 금액 합계입니다.

| 등급 | 누적 구매액 | 할인율 |
|---|---|---|
| 일반 | 0원 이상 | 0% |
| 실버 | 100,000원 이상 | 3% |
| 골드 | 300,000원 이상 | 5% |
| VIP | 1,000,000원 이상 | 10% |

### 오늘의 할인 (`DailyDeal`)
요일마다 한 카테고리를 할인합니다 (한국 날짜 기준).

| 월 | 화 | 수 | 목 | 금 | 토 | 일 |
|---|---|---|---|---|---|---|
| 식품 10% | 생활용품 10% | 패션의류 15% | 가전디지털 5% | 뷰티 15% | 스포츠/레저 10% | 완구/취미 10% |

결제 금액은 다음 순서로 계산합니다.
- **판매가** = 정가 − 오늘의 할인 (10원 단위 버림)
- **결제 금액** = 판매가 합계 − 등급 할인

주문할 때의 판매가가 주문 상품 가격으로 저장됩니다. 그래서 요일이 바뀌어도 주문 금액은 변하지 않습니다.

### 상품 옵션 (`ProductOption`)
- 옵션이 있는 상품은 옵션을 골라야 담거나 주문할 수 있습니다.
- 재고는 옵션마다 따로 셉니다. 상품 재고는 옵션 재고의 합계입니다.
- 옵션은 `products.sql`로 넣습니다.
  - 노트북 백팩: 15/17인치 × 화이트/블랙
  - 기능성 티셔츠: 블랙/네이비/버건디 × S/M/L/XL

### 재고 표시
- 손님에게는 재고가 2개 이하일 때만 "품절 임박 N개 남음"을 보여 줍니다. 판매량과 입고량이 그대로 드러나지 않게 하기 위해서입니다.
- 관리자에게는 항상 정확한 재고를 보여 줍니다.

| 문제 | 원인 | 해결 |
|---|---|---|
| 세션이 없는 상태에서 로그인하면 메인 화면이 깨짐 (관리자는 500 오류, 손님은 상품이 없는 빈 화면) | 로그인 직후 `/;jsessionid=...` 주소로 이동하는데, 이 주소는 `HomeController` 가 받지 못함 | `application.properties` 에 `server.servlet.session.tracking-modes = cookie` 추가 (세션 번호를 쿠키로만 주고받음) |
| 여러 사람이 같은 순간에 주문하면 재고보다 많이 팔림 (재고 1개에 동시 주문 20건 → 2건 성공), 일부 요청은 500 오류 (MySQL 교착 상태 `Deadlock found`) | 재고를 "읽기 → 빼기 → 저장"하는 사이에 다른 주문이 끼어들 수 있었음. 두 주문이 모두 재고 1개를 읽고 각자 0으로 저장함 | `OrderService` 에 비관적 잠금 추가 : 재고를 고치기 전에 상품 / 옵션 행을 잠그고(`SELECT ... FOR UPDATE`) 최신 재고를 다시 읽음. 다른 주문은 앞 주문이 끝날 때까지 기다림. 여러 상품은 상품 번호 순서로 잠가 교착 상태를 막음. 장바구니 주문, 바로 주문, 취소 / 거절 / 반품 승인에 모두 적용 |
| 상품 상세에서 상품명 위의 카테고리 이름(예: 패션의류)을 눌러도 아무 일도 일어나지 않음 | 누를 수 있을 것처럼 보이는 자리지만 글자만 있고 링크가 아님 | 카테고리 이름을 링크로 바꿔 그 카테고리 상품 목록(`/products?category=패션의류`)으로 가게 함. 마우스를 올리면 밑줄이 생김. 데님 일자 청바지 → 패션의류 상품 목록 7개로 이동하는 것 확인 |

### 확인하지 않은 것
- 관리자 상품관리의 **전체 상품 판매량 초기화** 버튼 : 실제 판매 기록이 모두 0이 되므로 누르지 않았습니다. 상품 하나씩 초기화하는 기능은 확인했습니다.

## 프로젝트 구조

```
src/main/java/kr/ac/kopo/gnuyog/goldstarmall
├── config/        보안 설정, 로그인 / 관리자 / 손님 전용 인터셉터, 초기 데이터(관리자 계정)
├── controller/    화면 요청 처리 (홈·상품, 회원, 장바구니, 주문, 알림, 상품평·문의, 관리자)
│                  + 모든 화면에 공통 값을 넣는 ControllerAdvice (등급, 알림 개수, 처리 대기 개수)
├── domain/        JPA 엔티티 (Member, Product, ProductOption, CartItem, Order, OrderItem, Review, Inquiry)
│                  + enum (ShippingStatus, MemberGrade, DailyDeal)
├── exception/     BusinessException, NotFoundException, 전역 예외 처리
├── repository/    Spring Data JPA 리포지토리 (구현 클래스는 Spring 이 자동으로 만든다)
├── service/       비즈니스 로직 (주문 / 환불 / 반품, 장바구니, 등급, 알림 등)
└── validator/     회원 / 상품 입력값 검사

src/main/resources
├── application.properties
├── sql/           products.sql (상품, 옵션), demo-data.sql (시연용 회원, 주문)
├── static/        css/style.css, js/common.js, images/products/상품번호.jpg
└── templates/     Thymeleaf 화면 (home, index, product, cart, order, member, admin, fragments)
```

### 데이터베이스 테이블

| 테이블 | 내용 |
|---|---|
| `members` | 회원 (손님 / 관리자, 등급) |
| `products` | 상품 (정가, 재고, 제조사, 원산지, 로켓 배송 여부) |
| `product_options` | 상품 옵션 (옵션 이름, 옵션 재고) |
| `cart_items` | 장바구니 항목 (회원, 상품, 옵션, 수량) |
| `orders` | 주문 (받는 사람, 배송지, 배송 상태, 결제 / 할인 / 환불 금액, 반품 정보) |
| `order_items` | 주문 상품 (주문 당시 가격, 수량, 옵션) |
| `reviews` | 상품평 (별점, 내용, 관리자 코멘트) |
| `inquiries` | 상품문의 (질문, 관리자 답변) |

## 상품 사진
`src/main/resources/static/images/products/` 폴더에 **상품번호.jpg** 이름으로 넣으면 사진이 보입니다.
사진이 없는 상품은 이모지 아이콘이 대신 보입니다.
상품번호는 관리자로 로그인하면 상품 상세의 '상품 정보' 표에서 확인할 수 있습니다.
